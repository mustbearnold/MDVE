# Gate v1 on one release candidate

MDVE may claim v1 only when one identified Git commit and byte-identical npm
tarball pass every product/security, reliability/fidelity, accessibility,
performance, installation, legal, and release-evidence gate. Weighted readiness
scores or evidence from different builds could hide a release-blocking failure;
the complete measurable contract and planning-PR-only GitHub Actions exception
are recorded in [the v1 release-gates decision](../../.scratch/mdve-v1/issues/05-define-v1-release-gates.md).
